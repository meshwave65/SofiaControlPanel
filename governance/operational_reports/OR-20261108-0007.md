# OperationalReport — OR-20261108-0007

## Objective

Persist the responsible user's explicit directive that agents working on a mission must ignore unrelated tables and data, especially in intentionally consolidated Supabase projects, and avoid scope expansion.

## Inputs, outputs, and tools

- Inputs: user clarification in current conversation; existing SCP AGENTS.md, operational lifecycle skill, MISSION_0018 task board.
- Outputs: added a mandatory “Escopo de dados e bancos por missão” section to AGENTS.md; this OR and index entry.
- Tools: GitHub file retrieval and update APIs.

## Execution summary

Added an agent-level rule: inspect only data directly relevant to the active mission/task and its acceptance criteria; do not broadly enumerate unrelated tables; determine table provenance in consolidated databases; do not make a global security claim from RLS counts; ignore unrelated data; and do not alter schemas, data, RLS, or migrations absent explicit authorization.

This is a documentation/governance change only. It does not inspect or alter database contents and does not change MISSION_0018 task status.

None observed.

## Evidence and uncertainty

The directive is grounded in the user's explicit instruction. Database composition, the stated intentionality of 29 tables without RLS, and the deferred OAuth migration remain owner-provided context, not an independent table-by-table audit. The directive intentionally avoids expanding the mission into such an audit.
