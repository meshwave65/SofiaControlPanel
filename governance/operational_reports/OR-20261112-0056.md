## Analysis and recommendation

Recommend evaluating an append-only internal MWN price-event ledger as the primary historical record.

Rationale:
- retains every effective price change, including multiple events on the same day;
- preserves temporal order and event provenance;
- supports reconstruction of the last known price at any point;
- allows daily closing values to be derived without losing intraday history;
- avoids imposing second-level polling before market activity justifies it.

Daily close should initially be derived from the event stream. A separate physical daily candle table should be considered only if measured query volume, latency or cost warrants materialization. A day without a price-change event should not create a fake change event; its close may carry forward the last known price with an explicit no-change/staleness indicator.

Candidate metadata for later schema evaluation includes event ID, asset, previous/new price, denomination/unit, effective timestamp, recorded timestamp, event type/source, correlated source operation, actor, reason/approval reference and applicable parameter/rule version. These are candidates only, not an approved schema.

The capture mechanism (database trigger, transactional function or explicit service write) cannot responsibly be selected until the existing price source and all update paths are inspected. Source update and event append must ultimately be atomic or equivalently protected against a price change without its historical event. Event correction should be represented by a corrective event rather than silent overwrite.
