# OperationalReport — OR-20261101-0001

> **Email do usuário:** não informado
> **Data e hora:** 2026-10-31 17:36 (UTC-03:00)

## Objective

Corrigir o falso início de missões no SofiaControlPanel. O painel alterava o status local, mas não chamava a API Manus, e o saldo dos agentes permanecia sem fonte real.

## Inputs, outputs, and tools

- Inputs: código de execução local, heartbeat, endpoint de créditos, schema PostgreSQL, documentação oficial Manus v2 e continuidade do projeto.
- Outputs: `server/manusExecutionService.ts`, `server/sofiaOrchestrator.ts`, `server/routers.ts`, `server/heartbeat.ts`, `server/handlers/creditMonitoringHandler.ts`, `server/db.ts`, `client/src/pages/Agents.tsx`, `client/src/pages/TaskDetail.tsx`, schema/migration Drizzle e documentação da MISSION_0016.
- Fontes externas: documentação oficial Manus para `task.create`, `task.detail`, `usage.availableCredits` e ciclo de vida de tarefas.
- Ferramentas: Git, pnpm, TypeScript, Vitest, Vite, esbuild e Drizzle Kit.

## Execution summary

A auditoria mostrou que o início anterior apenas alterava o status local; `creditMonitoringHandler` retornava `no_source_configured`; e `heartbeat.ts` calculava créditos com `Math.random()`. Foi implementado um cliente server-side que usa a API key criptografada do agente, chama `POST /v2/task.create`, persiste o `task_id` externo e consulta `task.detail` para sincronizar status, consumo e conclusão.

O heartbeat passou a sincronizar `usage.availableCredits` e tarefas Manus. Também foi criada a mutation `agents.refreshCredits` e um botão manual na tela de agentes. Missões antigas em `PROGRESS` sem `manusTaskId` podem ser recuperadas. A migration adiciona `manusTaskId`, `manusStatus`, `creditsUsed` e `lastSyncedAt` em `sofia.tasks`.

## Problems and workarounds

1. **Problema:** a implementação anterior apresentava início local sem execução externa. **Solução:** `tasks.start` agora despacha `task.create` e retorna erro claro quando não há agente ou API key.
2. **Problema:** saldo era simulado ou declarado indisponível. **Solução:** uso do endpoint oficial `usage.availableCredits`, com sincronização periódica e manual.
3. **Problema:** migration automática não pôde ser gerada sem `DATABASE_URL` real. **Solução:** Drizzle Kit gerou a migration usando URL sintética apenas para geração de arquivos; nenhuma conexão ou alteração em banco foi realizada no sandbox.

## Improvement proposals

- **P-001:** Adicionar polling de `task.listMessages` para importar o relatório final Manus como mensagem local. Benefício: resultados ficam visíveis dentro do painel; risco: volume e parsing de eventos; prioridade: alta; backward-compatible: sim.
- **P-002:** Adicionar lock/transação de dispatch para evitar duas chamadas `task.create` concorrentes para a mesma tarefa. Benefício: evita cobrança duplicada; risco: mudança de persistência; prioridade: alta; backward-compatible: sim.
- **P-003:** Configurar webhook Manus para reduzir latência em relação ao polling de cinco minutos. Benefício: status e créditos mais rápidos; risco: autenticação/endpoint público e retries; prioridade: média; backward-compatible: sim.
