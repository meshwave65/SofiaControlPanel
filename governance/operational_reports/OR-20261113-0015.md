## 1. Documented 29-table exception

Library evidence from the November 4 technical discussion records that 29 RLS-disabled tables belong to other projects/modules accidentally co-located in the shared Supabase project. The owner explicitly deferred those placeholder structures and stated they contain no sensitive data and are intentionally left without RLS while functionality is prioritized. They are outside the current MWN/MW-Ex remediation scope.

## 2. Current catalog reconciliation (read-only)

Catalog query against `pg_class` / `pg_namespace`:

- Public ordinary tables: **64**
- RLS enabled: **34**
- RLS disabled: **30**

The additional 30th table is **`public.mwex_business_configs`**.

Evidence:
- The table is part of the MW-Ex business configuration schema, not one of the legacy placeholder modules.
- It was created by migration `20261113124946`, named `mwex_scp_schema_base`.
- The migration creates the table and seeds nine active configuration records, but does not execute `ALTER TABLE ... ENABLE ROW LEVEL SECURITY` and does not create a policy for this table.
- The nine records configure fiat currencies, payment methods, market-order enablement, fees, hybrid split/conversion parameters, order limits, 2FA, matching mode, and payment confirmation mode.
- `pg_policies` reports **zero policies** for this table.
- `information_schema.role_table_grants` shows broad table privileges (including SELECT/INSERT/UPDATE/DELETE) granted to both `anon` and `authenticated`.
- The helper functions `mwex_config_bool(text,text)` and `mwex_config_numeric(text,text)` are SECURITY DEFINER and executable by both `anon` and `authenticated`.

This is a real MW-Ex configuration/security issue and is distinct from the documented 29 placeholders. It must not be dismissed under that exception.

## 3. Remediation status

- **No database changes were made.**
- No RLS was enabled, no grants were revoked, and no policies/functions were modified.
- Remediation should enable RLS on `mwex_business_configs`, remove direct anonymous/authenticated table mutation privileges, and define the minimum intended administrator/service access. Function execution grants and the SECURITY DEFINER helper exposure must be reviewed together so the intended business configuration can be read by operational RPCs without exposing a generic configuration oracle.
- This remediation is a database security migration and remains a separate execution gate; this diagnostic phase does not apply it.
