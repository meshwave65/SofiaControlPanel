# OperationalReport — OR-20261029-0007

## Objective

Implementar a API tRPC protegida de ARC/PGC no `SofiaControlPanel`, com procedures para registrar, consultar e listar avaliações, respeitando ownership/admin e mantendo `shadow` como modo padrão.

## Inputs, outputs, and tools

- Inputs: `AGENTS.md`, `governance/missions/0010/BLUEPRINT.md`, `MISSION_0010 - TASKS - PROGRESS.md`, checkpoint ARC-004 e schema ARC-004.
- Outputs: `server/db.ts`, `server/routers.ts`, `governance/missions/0010/CHECKPOINT-ARC-005.md` e este OR.
- Ferramentas: Git, pnpm, TypeScript, Vitest e GitHub remoto `meshwave65/SofiaControlPanel`.

## Execution summary

Foram adicionados helpers de banco para criar assessments e evidências em transação, consultar a avaliação mais recente e listar avaliações por tarefa. O acesso é limitado ao criador da tarefa ou a `admin`; consulta sem acesso se comporta como recurso não encontrado. A nova superfície `arc` contém `evaluateTask`, `getAssessment` e `listAssessments`. O modo default é `shadow`, há limites de tamanho/quantidade para entrada e `metadata` é removida das respostas.

O código foi publicado no commit [`e635492`](https://github.com/meshwave65/SofiaControlPanel/commit/e6354926cc63b8566ed0d2f8c96013311a257ef2). O checkpoint foi publicado separadamente em [`bd64b82`](https://github.com/meshwave65/SofiaControlPanel/commit/bd64b820d14a35de1038f4653c7a33796e2e5123), com `CHECKPOINT-ARC-005.md`.

## Problems and workarounds

1. A primeira compilação encontrou incompatibilidade entre a assinatura de `z.record` do Zod 4 e o uso de um único argumento. O schema foi corrigido para declarar explicitamente tipo de chave e tipo de valor.
2. O avaliador/coletor ARC ainda vive no repositório separado `SofiaARC-PGC`. Para não duplicar lógica Bayesiana nem alegar integração inexistente, ARC-005 implementa a fronteira de persistência de uma avaliação já calculada; a integração end-to-end ficou explicitamente para ARC-006.
3. A migration ARC-004 não foi executada contra banco real nesta unidade. O risco residual é a ausência de confirmação end-to-end com PostgreSQL provisionado.

## Evidence and uncertainty

Confirmado: `pnpm check` passou; os testes existentes `server/db.test.ts` e `server/auth.logout.test.ts` passaram, totalizando 5 testes; `git diff --check` passou; os dois commits estão em `origin/main`.

Não confirmado: execução contra PostgreSQL real, existência de policy seed correspondente ao `policyId` recebido, conexão com o coletor ARC-003 e comportamento da UI. O endpoint deve ser tratado como boundary protegida de persistência até ARC-006 adicionar o avaliador interno.

## Improvement proposals

- **ARC5-P1:** adicionar teste de integração tRPC+PostgreSQL cobrindo ownership, admin, shadow default e isolamento de metadata. Benefício: comprovar o contrato real; risco: depender de banco de teste; prioridade alta; backward-compatible.
- **ARC5-P2:** fazer ARC-006 chamar o avaliador ARC-003 internamente, eliminando a aceitação de probabilidades calculadas pelo chamador como fonte final. Benefício: reduzir adulteração e duplicação; risco: integração entre repositórios; prioridade alta; backward-compatible se mantiver o contrato durante transição.

## Privacy, safety, and scope review

Não foram armazenadas nem reproduzidas credenciais. A API exige procedimento protegido, aplica ownership/admin e omite metadata das evidências na saída. `shadow` é default e não bloqueia tarefas. Não foram habilitados modos `assisted` ou `enforced`. O endpoint não substitui autenticação nem prova de presença.
