# OperationalReport — OR-20261114-0021

## Objective
Registrar requisitos propostos para identificação da execução Manus associada às missões e comunicação direta com a conta original do agente, independente da atribuição atual à missão.

## Inputs and evidence
- Proposta explícita do responsável: exibir Agent Task ID e permitir enviar mensagens diretamente à conta original do agente mesmo quando ele não estiver mais ativo/atribuído à missão.
- Inspeção estática de server/manusExecutionService.ts: createManusTask cria execução por /task.create; sendManusMessage usa /task.sendMessage com task_id; getManusCredentialsForAgent resolve a credencial pela atribuição agentId da tarefa.
- Inspeção estática do Messenger e do fluxo de mensagens: o envio atual é centrado na execução Manus associada à missão.
- A API não foi consultada externamente nesta etapa; não foi confirmado endpoint de inbox genérica por conta.

## Requirements captured
1. **Identificadores distintos e visíveis:** Mission ID identifica a missão local; Agent ID identifica o agente/conta; Agent Task ID (Manus Task ID) identifica a execução externa específica. Exibir o Agent Task ID nos detalhes da missão e, quando útil, na lista, com ação de copiar. Se não houver execução externa, indicar ausência de forma explícita.
2. **Conversa direta com a conta original:** permitir abrir um canal de conversa endereçado ao agente/conta Manus cadastrada, sem depender de ele continuar atribuído à missão. O canal usa a credencial vinculada ao Agent ID e mantém histórico próprio, separado do ciclo da missão.
3. **Contexto controlado:** permitir que o operador selecione/forneça contexto de missão (resumo, ID e artefatos relevantes). Não injetar automaticamente todas as missões, credenciais, dados privados ou histórico irrestrito.
4. **Isolamento de efeitos:** mensagens e respostas do canal direto não alteram status, atribuição, Draft, execução ou conclusão de uma missão. Incorporar conteúdo à missão exige ação explícita.
5. **Entrega verificável:** a UI deve distinguir mensagem registrada no SCP, envio aceito pela API, eventual confirmação de recebimento/processamento disponível e resposta recebida. Não declarar que chegou a uma inbox ou foi lida pelo agente sem evidência.

## Technical hypothesis and validation gate
O código conhecido usa /task.sendMessage com task_id e /task.create para criar uma execução. Não foi identificado endpoint de inbox genérica do agente. Caso a API Manus não ofereça esse canal, avaliar uma execução Manus dedicada e persistente por conversa/agente, criada sob a credencial do agente e reutilizada para mensagens subsequentes. Essa é uma hipótese de implementação, não um endpoint confirmado. Validar documentação/contrato da API e comportamento de entrega antes de implementar.

O Agent Task ID da missão não deve ser confundido com a identidade permanente do agente, nem reutilizado como ID do canal direto.

## Scope and safety
Nenhum código ou schema foi alterado. Nenhuma credencial foi lida ou modificada. Nenhuma chamada Manus/LLM, mensagem, dispatch, consumo de crédito, escrita em banco, deploy ou restart foi executado. Task 20.3 permaneceu intocada.

## Oracle handoff
Avaliar os requisitos e validar o contrato oficial da API Manus. Depois, especificar persistência e UX do canal direto, contexto selecionável, estados de entrega e autorização de acesso à conta. Preservar isolamento entre conversa direta e ciclo de missão.
