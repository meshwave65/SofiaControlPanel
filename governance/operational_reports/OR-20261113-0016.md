## 1. Source-of-truth verification (read-only)

The canonical public.mwc_sale_prices table contains an enabled BRL row:
- currency = BRL
- enabled = true
- price_per_mwc = 0.02160500
- updated_at = 2026-10-24 14:01:37.258205+00

The enabled EUR row is 0.00382918. The BRL reference exists; the UI must not report it as absent.

## 2. Frontend diagnosis

In src/pages/MwExOrderPreview.jsx, the preview creates its Supabase client from browser-side VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY and queries mwc_sale_prices directly.

The component catch block discards the Supabase error and sets mwnReference to null. This converts an access-denied response into the misleading label “Referência indisponível”.

## 3. RLS diagnosis

Read-only catalog inspection confirms:
- RLS is enabled on public.mwc_sale_prices.
- SELECT policy mwc_prices_select_enabled_or_admin targets only the authenticated role and permits enabled rows or the sale administrator.
- The preview route is public at the application level and does not establish a Supabase authenticated session.
- The browser uses a publishable key; anonymous requests do not satisfy the policy's authenticated role requirement.

Therefore, the row exists but the preview's current anonymous read path is blocked by RLS. This is an access-path defect, not missing price data.

## 4. Safe remediation recommendation

Use a server-side, read-only endpoint that queries the canonical table with a server-only Supabase secret and returns only the enabled BRL reference fields required by the UI (price_per_mwc, updated_at). Keep the secret out of all VITE_* variables and browser bundles.

Do not disable RLS, add anonymous SELECT on the full table, expose a service/secret key to the browser, hardcode the current price, or alter acquisition history, ledger, order engine, or financial rules.

Vercel currently has SUPABASE_KEY configured as a publishable sb_publishable_... key; no server-only Supabase secret is configured for this endpoint. Provisioning a server-only secret and wiring the narrow endpoint is therefore a security-sensitive configuration change requiring owner approval.

## 5. Changes and validation

- No repository code changed in this diagnostic phase.
- No Supabase schema, policy, grant, or data changed.
- No Vercel environment variable changed.
- PR #25 remains open and unmerged; production remains unchanged.
- The exact source row and RLS policy were verified read-only. Runtime correction and UI validation remain pending the approved secure read path.

## 6. Next gate

Obtain approval to provision a server-only Supabase secret for the Vercel serverless runtime, then implement a narrowly scoped endpoint and switch the MWN UI to that endpoint. Preserve the existing RLS policy and expose only the BRL reference value and timestamp.
