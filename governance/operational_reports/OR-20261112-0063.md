# OR-20261112-0063 — Stale market quote and automatic recovery behavior

- **Mission:** MISSION_0021
- **Task:** 21.5 — MWN price and economic parameter governance
- **Date:** 2026-11-12
- **Status:** SUBMITTED
- **Scope:** Record owner-defined behavior when the market-price source is unavailable or invalid
- **Database/code changes:** None

## Owner clarification

The owner confirmed the fail-safe behavior:

- If the market source becomes unavailable or supplies invalid data, the system must continue displaying the **last available quotation**.
- That quotation must be explicitly marked as **outdated/stale**, with a prominent visual warning; red was suggested as a possible treatment.
- The system must not present the stale quotation as current, fabricate a replacement, or accept a manually entered price as a substitute.
- When the restriction condition is cleared and valid market data becomes available again, the system returns to normal operation.

## Required state behavior

The interface and backend should distinguish at least:
1. **CURRENT:** a valid quotation within the approved freshness window.
2. **STALE / RESTRICTED:** the last known quotation is retained for reference, clearly marked outdated; normal price-dependent operation remains subject to the restriction policy.
3. **RECOVERED:** a new valid quotation has passed source, integrity, and freshness checks; the system can return to CURRENT and resume normal operation.

The stale value is retained as historical/reference information only. It must never be relabeled as current merely because it is the most recent value stored.

## Recovery and audit requirements

- Recovery must be triggered by receipt and validation of a new valid market quotation, not by an administrator manually clearing a warning.
- The system should retain the outage/invalid-data interval, last valid quotation timestamp, reason/status, recovery timestamp, and the first accepted post-recovery quotation.
- The stale warning should clear automatically only after the approved recovery checks pass.
- Visual treatment (including red) is a UI decision; the semantic status and operational restriction must be enforced independently of color.
- Exact freshness thresholds, validation criteria, and which price-dependent operations are blocked during STALE / RESTRICTED remain to be specified. The owner's clarification establishes stale display and automatic recovery, but does not by itself authorize transactions to execute using the stale price.

## Relationship to the no-manual-intervention rule

This behavior complements OR-20261112-0062. During a source outage or invalid-data condition, the system retains and labels the last valid quote; no human, including the owner, may manually replace or override the market price. Once a valid source quotation is restored, the system resumes normal operation automatically.

## Safety boundary

This OR records the owner's clarification and derived operational requirements only. It does not select the market source, set freshness thresholds, change transaction permissions, modify schema/code, deploy, or perform financial operations. No Supabase data or production system was modified.
